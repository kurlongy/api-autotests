BUG-001 — API принимает запрос на создание пользователя без обязательного email

Окружение

- API: JSONPlaceholder
- Endpoint: "POST /users"
- Method: POST
- Format: JSON
- Инструмент проверки: Python + pytest + requests

Предусловия

API доступно и принимает POST-запросы.

Шаги воспроизведения

1. Отправить POST-запрос на "/users".
2. Передать данные пользователя без поля "email".

Пример запроса:

{
  "name": "QA Test",
  "username": "qa_test"
}

Ожидаемый результат

API должно проверить обязательные поля и вернуть ошибку валидации:

- HTTP Status: "400 Bad Request"
- В ответе указано, какое обязательное поле отсутствует.

Фактический результат

Для учебного сценария предполагается, что API принимает запрос без "email" и возвращает успешный ответ.

Severity

Medium

Проблема не приводит к падению сервиса, но позволяет создавать некорректные данные.

Priority

Medium

Дефект стоит исправить, если "email" является обязательным полем по требованиям продукта.

Влияние

В систему могут попадать пользователи с неполными данными. Это может привести к проблемам при последующей работе с такими пользователями.

Рекомендация

Добавить серверную валидацию обязательных полей при создании пользователя и возвращать "400 Bad Request", если обязательные данные отсутствуют.

Примечание

Данный bug report является учебным примером. Он демонстрирует структуру описания дефекта: окружение → шаги воспроизведения → ожидаемый результат → фактический результат → severity/priority → влияние.
